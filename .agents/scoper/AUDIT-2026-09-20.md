## Temuan prioritas

### P0 / HIGH

1. Register allocation race: `InventoryItem.php` menghitung `max(register)+1`, lalu service melakukan bulk insert tanpa lock parent row. Concurrent add dapat menghasilkan duplicate-key failure. Perlu locking/serialization dan concurrency test.
2. Compose mempublikasikan PostgreSQL `5432` dan Redis `6379` ke host, serta memakai credential fixed/default. Hapus host ports atau bind loopback/private network; inject secrets.
3. Compose mengizinkan `APP_KEY` kosong. Tambahkan fail-fast validation untuk production.
4. Planning/status provenance tidak konsisten. Buat verification cycle evidence-based; jangan percaya label `Done` tanpa command/output.

### P1 / MEDIUM

5. `per_page` inventory/users tidak dibatasi. Clamp 1..100 dan test.
6. API login tidak menunjukkan throttle. Tambahkan rate limit berbasis IP/account dan test 429.
7. Delete inventory permanen tanpa audit trail. Putuskan soft delete atau hard delete dengan activity log dan retention policy.
8. API contract drift: SPEC menyebut `/api/v1/auth/user`, implementasi menyediakan `/api/v1/auth/me`.
9. Permission PATCH inventory memakai `inventory.unit.condition.update`; pisahkan `inventory.update` dari unit-condition permission.
10. Risiko N+1 pada inventory list/dashboard; gunakan aggregate query/withCount dan query-count test.
11. `APP_URL` production masih berdefault `http://localhost:8000`; dokumentasikan TLS/reverse proxy dan validasi production URL.
12. PostgreSQL parity dan object-level authorization/IDOR belum terbukti runtime.
